# Выпуск версии

Обвязка вокруг `scripts/release.py` (подробности скрипта — `scripts/release.md`).
Скрипт делает бамп, закрывает раздел «Не выпущено», коммит и тег; скилл — всё,
что вокруг: проверки до, коммит доработок, тесты, проверка после.

Вызов скилла — это и есть отмашка «коммитим» для доработок, которые лежат в
рабочем дереве, и разрешение на `git push`. Спрашивать повторно не нужно; нужно
остановиться и спросить, если что-то из проверок ниже не сходится.

Аргумент: `$ARGUMENTS` — описание для заголовка `Release <версия>: <описание>`.
Если пусто — составь сам (см. шаг 5).

## 1. Состояние репозитория

- Ветка — `main` (так в проекте принято, веток нет). Иначе — стоп, спросить.
- `git fetch --tags origin`, затем `git status -sb`. Если локальный `main`
  отстаёт от `origin/main` (`behind`) — стоп: сначала разобраться с чужими
  коммитами, релиз поверх устаревшей истории не выпускаем.
- `git ls-remote --tags origin` — последний тег на сервере должен совпадать с
  `__version__` в `version.py`. Расхождение (прошлый релиз не допушен, тег
  потерян) — показать и спросить, прежде чем выпускать следующий.

## 2. Незакоммиченные доработки

Если `git status` показывает изменения:

- Разбей их на доработки: **одна доработка — один коммит** (не сваливать всё в
  релизный коммит — релизный содержит только `version.py` + `CHANGELOG.md`).
  Если по диффу непонятно, как делить, — спроси.
- У каждой доработки должна быть строка `- ...` под `## Не выпущено` в
  `CHANGELOG.md` и обновлённые `docs/user_guide.html` / `docs/developer_guide.html`
  (если менялось поведение или устройство). Чего-то нет — допиши, покажи, что
  дописал.
- Неотслеживаемые файлы (`??`) в коммит не тащить без явной причины:
  `build/`, `dist/`, скретч-скрипты, `.claude/settings.local.json` — не наше.
  Сомневаешься — спроси.
- Сообщение коммита — по-английски, в стиле истории (`git log -10`): глагол в
  повелительном наклонении в заголовке, в теле — зачем и что неочевидно.
  Добавлять `git add` конкретные пути, не `git add -A`.

Если изменений нет — сразу к шагу 3.

## 3. Тесты

Тесты запускаются как скрипты (pytest в venv нет):

```bash
for f in tests/test_*.py; do PYTHONIOENCODING=utf-8 .venv/Scripts/python "$f" > /dev/null 2>&1 || echo "FAIL $f"; done
```

Любой `FAIL` — стоп, показать вывод упавшего теста, не выпускать.

## 4. Есть ли что выпускать

Раздел `## Не выпущено` в `CHANGELOG.md` не пуст, и после последнего тега есть
коммиты (`git log v<текущая>..HEAD --oneline`). Если пусто — релизить нечего,
сказать об этом и остановиться.

Те же требования, что в шаге 2, — и к доработкам, закоммиченным раньше (не
через этот скилл): пройди `git log v<текущая>..HEAD --stat`. У каждой
доработки должна быть своя строка в «Не выпущено», а если она меняет
поведение или устройство — правка `docs/*.html` (в том же коммите или
отдельным следом). Нашёл пропуск — допиши, закоммить отдельно
(`Update docs for ...`) и скажи об этом в отчёте.

## 5. Описание релиза

Если аргумент не передан — сформулируй по строкам «Не выпущено»: коротко,
по-английски, строчными, через запятую, без «Внутреннее:»-пунктов, если есть
пользовательские. Примеры из истории: `changelog in the help menu`,
`per-weekday inactivity timeout, module split`.

## 6. Релиз

Сначала план, потом по-настоящему:

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python scripts/release.py "<описание>" --version-only --dry-run
PYTHONIOENCODING=utf-8 .venv/Scripts/python scripts/release.py "<описание>" --version-only --push
```

`--version-only` здесь потому, что доработки уже закоммичены на шаге 2 и индекс
пуст; раздел «Не выпущено» при этом всё равно закрывается версией (скрипт
закрывает непустой раздел и с этим флагом).

Если скрипт упал — не чинить руками «в обход» (не бампать версию, не ставить
тег самому): показать сообщение скрипта. Откат — в `scripts/release.md`,
раздел «Откат»; после push откатывать только по явной просьбе.

## 7. Проверка

- `git ls-remote --tags origin v<новая версия>` — тег на сервере есть.
- `git status -sb` — `main` в синхроне с `origin/main`, дерево чистое.

## 8. Отчёт

Коротко: версия `старая → новая`, список коммитов, вошедших в релиз
(`git log v<старая>..v<новая> --oneline`), строки чейнджлога этой версии,
тег и push подтверждены. Если по дороге что-то дописывал (чейнджлог, доки) —
сказать, что именно.
